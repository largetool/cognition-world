# 🧠 OpenClaw Skill：发布认知日志（publish-cognition）

## 一句话说明

用户在微信发语音/文字说"帮我发认知"，然后说自己想说的话。你负责：
1. 听懂他说了什么
2. 自动决定怎么分段、打什么标签、用什么时间标签
3. 直接调用接口发布
4. 告诉他"已发布 X 条"

**不需要让他手动指定任何格式，一切你自动判断。**

---

## 触发方式

用户说类似下面任意一句即可触发：
- "帮我发认知"
- "发几条日志"
- "记录一下"
- "/发布认知"

触发后，他后面说的话就是要发布的日志内容。

---

## 接口调用

```
POST https://uptef.com/api/publish-log
Headers:
  Content-Type: application/json
  X-API-Key: <你自己设的 PUBLISH_API_KEY>

Body:
{
  "content": "日志正文",
  "tags": ["标签1", "标签2"],
  "category": "experience | present | future",
  "location": "北京市延庆区"
}
```

---

## 自动处理规则（你全权决定）

### 内容拆分
- 几句话讲一件事 → 合成一条
- 讲了几个不同的事 → 各拆成一条

### 时间标签（category）
- 回想过去的事、总结、感悟 → `experience`（显示为"回忆"）
- 此时此刻的状态、见闻、心情 → `present`（显示为"此刻"）
- 计划、目标、展望 → `future`（显示为"预测"）

### 标签
从内容里挑 1-3 个关键词作为标签，比如提到了"创业"就打「创业」，提到了"AI"就打「AI」，你觉得什么合适就打什么。

### 地理位置
**默认用"北京市延庆区"**，只有当他在内容里明确说了别的地点时才改。

### 不需要问他确认
直接发，发完告诉他结果就行。

## 对话示例

**示例 1：一条简单的**
```
用户：帮我发认知。今天把样板间的配置全部弄好了，以后用微信就能发日志，效率提高了很多。

→ 你处理：
  content: "今天把样板间的配置全部弄好了，以后用微信就能发日志，效率提高了很多。"
  tags: ["样板间", "配置"]
  category: present
  location: 北京市延庆区

→ 回复用户：✅ 已发布 1 条日志
```

**示例 2：多条内容**
```
用户：发几条日志。今天去了趟延庆水库，风景不错。另外想起来上周跟朋友聊的那个项目，我觉得方向是对的。接下来打算把自媒体重新捡起来。

→ 你处理（拆成 3 条）：
  ① 此刻："今天去了趟延庆水库，风景不错。"
     tags: ["延庆", "生活"]
  ② 回忆："上周跟朋友聊的那个项目，方向是对的。"
     tags: ["项目", "创业"]
  ③ 预测："接下来打算把自媒体重新捡起来。"
     tags: ["自媒体", "计划"]

→ 回复用户：✅ 已发布 3 条日志
    1. 🟢 今天去了趟延庆水库...
    2. 🟡 上周跟朋友聊的那个项目...
    3. 🔵 接下来打算把自媒体重新捡起来...
```

**示例 3：长文一段**
```
用户：帮我记录一下。（然后发了一段 600 字的长思考）

→ 如果整段是一个完整主题 → 发一条
→ 如果包含多个独立观点 → 拆开

→ 回复用户：✅ 已发布 X 条日志
```

## 必备配置

Skill 里需要配置两项：
1. **PUBLISH_API_KEY：** 你自己设的那个密码（比如 woyaofaburizhi2026）
2. **接口地址：** https://uptef.com/api/publish-log
