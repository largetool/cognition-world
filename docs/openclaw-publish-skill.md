# 🧠 OpenClaw Skill：发布认知日志（publish-cognition）

## 一、Skill 信息

- **名称**：publish-cognition
- **触发命令**：`/发布认知` 或 `/publish-cognition`
- **功能**：将用户发来的内容整理后，发布到认知界网站（uptef.com）的个人日志专栏
- **渠道**：微信 / Telegram / 任何接入 OpenClaw 的聊天工具

## 二、前置准备

### 2.1 服务端环境变量（在 Vercel 项目设置中配置）

| 变量名 | 说明 | 获取方式 |
|--------|------|----------|
| `PUBLISH_API_KEY` | 自定义 API 密钥 | 自己设一个，比如 `rzj-publish-2026` |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase 管理密钥 | Supabase Dashboard → Settings → API → `service_role key` |
| `ADMIN_USER_ID` | 管理员的 user_id | 登录认知界 → 在个人页 URL 中查看 → `/user_id` 部分 |

### 2.2 接口地址

```
POST https://uptef.com/api/publish-log
Headers:
  Content-Type: application/json
  X-API-Key: <PUBLISH_API_KEY>

Body:
{
  "content": "日志正文（必填，最多5000字）",
  "tags": ["GEO", "AI", "独立开发"],
  "category": "experience | present | future",
  "location": "北京市海淀区"
}
```

**成功响应：**
```json
{
  "success": true,
  "log": { "id": "...", "content": "...", ... },
  "message": "日志发布成功"
}
```

**失败响应：**
```json
{
  "success": false,
  "error": "错误原因"
}
```

## 三、Skill 工作流程

### 3.1 解析用户输入

用户可能发来以下几种输入，AI 需要按类型处理：

**类型 A：简短想法（一条日志）**
> 用户："今天想明白一件事，合规不是限制而是边界，知道什么不能做反而更自由"

→ 直接生成一条日志，AI 自动提取标签、选择分类、判断是否需要地理位置

**类型 B：长文/多段内容（拆成多条）**
> 用户发了一段 800 字的思考

→ AI 按语义拆成 2-5 条日志，每条独立发布，分批询问确认

**类型 C：已经带格式的内容**
> 用户："[此刻] 在咖啡馆写代码 #独立开发 #GEO 今天把 API 调通了"

→ AI 解析方括号中的分类、井号标签、剩余内容作为正文

**类型 D：语音转文字**
> 用户通过微信语音输入，OpenClaw 自动转文字后传入

→ AI 按普通文字处理，必要时润色语句使其更通顺

### 3.2 三个分类的定义

| 分类 | 关键词 | 说明 |
|------|--------|------|
| `experience`（经历） | 回想、以前、过去、曾经、学到了 | 对过往的总结复盘 |
| `present`（此刻） | 现在、今天、正在、刚刚、发现 | 当下的状态和观察 |
| `future`（将来） | 计划、打算、希望、目标、预测 | 对未来的规划和展望 |

AI 应**自动判断分类**，只有当无法判断时才询问用户。

### 3.3 标签提取规则

- 从内容中提取 1-5 个标签
- 标签用中文或英文均可
- 优先提取：项目名、技术名词、领域关键词、地名词
- 例如：`#GEO #独立开发 #合规 #AI`
- 标签统一转为数组格式：`["GEO", "独立开发", "合规", "AI"]`

### 3.4 地理位置

- 选填字段
- 如果内容中提到地点（如"在 Starbucks"、"今天去了故宫"），自动提取
- 如果没有明确地点则不填
- 用户也可以手动指定，如 `[北京]` 或 `@上海`

## 四、Skill 命令设计

### 命令式用法（推荐）

用户直接发内容，AI 处理后发布：

```
你: 今天终于把样板间模式部署好了，合规风险降到最低
AI: ⏳ 正在处理...
AI: 📝 已整理为：
    分类：此刻
    标签：样板间, 合规, 开发
    内容：今天终于把样板间模式部署好了，合规风险降到最低
    确认发布？(回复"确认"或"取消")

你: 确认
AI: ✅ 日志已发布！https://uptef.com/rzj123
```

### 带参数用法

```
你: /发布认知 今天试了试从微信发日志，以后效率高多了 #OpenClaw #开发 [此刻]
AI: ✅ 日志已发布！
```

## 五、特殊处理逻辑

### 5.1 长文拆分

如果内容超过 500 字，AI 自动判断是否需要拆分：
- 一段完整叙事 → 保持一条
- 多个不连续观点 → 拆成多条

拆分后询问用户：
```
AI: 检测到内容较长，建议拆分为 3 条发布：
    1. [经历] xxx
    2. [此刻] xxx  
    3. [将来] xxx
    全部发布？或逐条确认？
```

### 5.2 频率控制

- 每次发布前检查是否成功，如果失败则提示用户
- 建议每条之间间隔至少 3 秒（已由 API 处理，无需手动控制）
- 如果批量发布有多条失败，重试失败项并报告结果

### 5.3 错误处理

| 错误 | 处理方式 |
|------|----------|
| API Key 无效 | 提示用户检查 PUBLISH_API_KEY 配置 |
| 内容超长 | 提示用户缩短或自动拆分 |
| 网络错误 | 重试 2 次，仍失败则提示 |
| 服务器错误 | 提示稍后再试 |

## 六、完整示例

### 示例 1：语音输入处理

```
用户（语音转文字）：
"今天在望京这边，突然想到认知界这个项目其实不只是个产品，它更像个社会实验，用AI把人的认知碎片串起来形成集体智慧"

AI 处理：
{
  "content": "在望京突然想到，认知界这个项目不只是个产品，更像一个社会实验——用AI把人的认知碎片串起来，形成集体智慧。",
  "tags": ["认知界", "AI", "社会实验"],
  "category": "present",
  "location": "北京市朝阳区望京"
}

→ 确认后调用 API 发布
```

### 示例 2：结构化输入

```
用户：
/发布认知 经历了几个月的开发，认知界终于进入了样板间阶段
回想起来，最大的收获不是代码写得多好，而是学会了判断什么该做什么不该做
#创业 #合规 #样板间 [经历]

AI 直接发布（无需确认，因为参数完整）：
{
  "content": "经历了几个月的开发，认知界终于进入了样板间阶段。回想起来，最大的收获不是代码写得多好，而是学会了判断什么该做什么不该做。",
  "tags": ["创业", "合规", "样板间"],
  "category": "experience"
}

→ 发布 → 返回 ✅ 日志已发布！
```

### 示例 3：长文批量

```
用户：
（一段 600 字的长文，包含三个不同的观点）

AI 拆分为 3 条：
1. [经历] 回顾项目启动以来的心路历程...
2. [此刻] 目前样板间的状态和数据...
3. [将来] 接下来自媒体推广的计划...

AI：检测到内容包含3个独立观点，建议拆分为3条发布：
  ① 经历 - 回顾项目启动以来的心路历程...
  ② 此刻 - 目前样板间的状态和数据...
  ③ 将来 - 接下来自媒体推广的计划...
  回复"全部发布"或输入序号单独发布

用户：全部发布
AI：✅ 已发布 3 条日志！
```

## 七、安装步骤

1. 在 OpenClaw 控制台中创建新 Skill
2. 将本文档内容粘贴为 Skill 的 System Prompt
3. 设置触发命令为 `/发布认知`
4. 确认 Vercel 上已配置好三个环境变量（PUBLISH_API_KEY、SUPABASE_SERVICE_ROLE_KEY、ADMIN_USER_ID）
5. 测试：在微信中发送一条测试内容
